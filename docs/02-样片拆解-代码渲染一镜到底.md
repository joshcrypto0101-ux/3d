# 样片拆解：《一张草图，盖成一栋楼》是怎么做的，以及表格里的 6 个视频能不能照这个方法依次做

日期：2026-10-14
样片：`x.com/AndyL5cc/status/2109977911738675625`（用户给的 `…/2110056844819632283` 是转发评论）
关键帧：`refs/sample-house/`

---

## 0. 结论

1. **样片不是 AI 视频生成，也不是实拍，是「用代码渲染出来的 3D 动画」。** 证据写在画面里：开场是 Claude Code 终端逐字打出提示词「把这张草图，盖成一栋真房子」；结尾字幕「本片每一帧都是 Claude 写的代码 · 11,8xx 行」。整段 60 s 只有 1 次硬切（结尾进室内），其余是一个连续运动的虚拟镜头（作者标签 #一镜到底），60 fps，画面上所有文字（HUD、天数、用料计数、双语字幕）都是矢量叠加，没有任何 AI 生成式画面的抖动或乱码。
2. **这正好是本仓库 `docs/01` 里推荐给 05 / 06 的那条「Remotion + 程序绘制」路线。** 样片证明这条路线不只能做教学图表，还能做有叙事、有镜头运动、有情绪的成片。
3. **6 个视频能依次做，而且可以共用一套代码工程。** 05 电阻指南、06 电容指南是直接对应；01–04 焊接视频用这套方法做出来的是「风格化微缩 3D 焊接动画 + 工程 HUD」，而不是提示词原文想要的「电子显微镜实拍质感的解压视频」。这一点要先拍板（§5）。
4. 依次做的顺序建议：**先搭共用工程 → 03 RP114 LDO（器件最少，1 条跑通管线）→ 02 → 01 → 04 → 05 → 06**，或者 05 先行。理由见 §6。

### 1.2 它用到的 10 个手法（这些就是我们要复刻的）

| # | 手法 | 在样片里 | 怎么实现 |
|---|---|---|---|
| 1 | **「提示词即开场」** | 终端框 + 光标逐字打字，Claude Code 星标 logo | React 组件，按帧 slice 字符串 |
| 2 | **假的「处理过程」HUD** | SCAN / EDGES / CORNERS / DESKEW；SHEETS 1/7 DWG PDF A3；坐标角标 | 纯 CSS/SVG，等宽小字，青色数值；让观众觉得「AI 真的在干活」 |
| 3 | **手绘 → 矢量的变形** | 歪线拉直成 CAD 图 | 同一组 SVG path，起点是加了噪声/抖动的坐标，终点是规整坐标，按帧插值 |
| 4 | **一镜到底的虚拟摄像机** | 从桌面俯冲到村庄、环绕、升高、拉远，无剪辑 | 摄像机位置/目标沿样条曲线按时间插值；章节切换只靠镜头运动 + HUD 淡入淡出 |
| 5 | **移轴微缩感** | 远近都模糊，只有主体清晰 | 景深后处理（DoF / tilt-shift pass），低饱和、低多边形、柔光 |
| 6 | **过程可视化而非结果展示** | 砖一块块出现、脚手架长高、X 光线框、楼层爆炸拆解 | InstancedMesh + 按索引的出现时间；clipping / 透明度；每层 y 偏移动画 |
| 7 | **数据驱动的计数器** | 第 N 天、砖 / 钢筋 / 混凝土、工程量标注 | 一份 JSON 时间表：每个阶段的起止帧 + 累计用量，HUD 读同一份数据，所以数字和画面永远一致 |
| 8 | **双语字幕 + 橙色关键词 + 逐字出现** | 中文大字 + 英文衬线小字 | 字幕数组 `{from, to, zh, en, highlight}`，逐字显现 |
| 9 | **粒子讲情绪** | 鞭炮、落叶、雪、烟花 | 简单 GPU 粒子或 Points，各 200–2000 个 |
| 10 | **结尾数据卡 + 元信息** | 总用量、造价、代码行数、原始 prompt | 普通 React 布局；「代码行数」是传播钩子 |

### 1.3 技术栈判断

从画面能确定的：WebGL 风格的实时渲染质感（而非 Blender Cycles 的离线光追），HTML/CSS 级别的文字排版（抗锯齿、字距、下划线、等宽字体混排），60 fps 逐帧确定性输出。最符合的组合是：

- **Remotion**（时间轴、逐帧渲染、字幕/HUD 用 React + CSS）
- **Three.js / React Three Fiber**（3D 场景，经 `@remotion/three` 或自建的「按帧推进时间」挂进 Remotion）
- 后处理：DoF / Bloom（`postprocessing` 库）
- 配乐后期贴上（音轨是均匀的音乐，没有人声）

也可能是纯 Three.js + Puppeteer 逐帧截图再 ffmpeg 合成，效果一样，但 Remotion 做 HUD 和字幕省事得多。我们自己做选 **Remotion + R3F**，这也是表格 sheet 5 / 6 提示词里点名要的工具。

作者说「11,8xx 行代码」，按 Claude Code 的工作方式，这是迭代几十轮的结果，不是一条提示词出来的（评论区有人问「提示词不能只是字幕内容吧」，作者答「总结好了明天发」，截至今天没搜到那篇总结）。

## 3. 把样片的方法映射到表格里的 6 个视频

### 3.1 焊接视频（sheet 1–4）用样片方法做出来是什么样

样片是「草图 → 房子」，我们是「原理图 → 板子」。一一对应：

| 样片 | 焊接视频对应 |
|---|---|
| 终端打提示词「把这张草图，盖成一栋真房子」 | 终端打「用 IP5306 做一块移动电源，2 oz 铜，1206 封装」 |
| 扫描手绘草图 → 拉直成 CAD 平面图 | **原理图闪现**（提示词第 6 条）：数据手册的典型应用电路 PNG → 矢量原理图逐线亮起 → 转成 PCB 布局图（`LAYOUT 布板 · 2 层 · 2 oz`） |
| 平面图放线到地面 | PCB 布局图「落」到空板上，焊盘和丝印逐个显现 |
| 挖基槽、钢筋、浇筑 | 钢网刮锡膏：锡膏按焊盘逐个出现 |
| 每一块砖按顺序砌 | **每个器件按 BOM 顺序放置**（提示词第 5 条）：镊子从画外进入、夹住器件、落到焊盘。天数计数器改成「器件 3/25 · C1 10 µF 1206」 |
| 封顶鞭炮 | **热风熔焊特写**：焊盘上的锡膏从颗粒灰变成亮银、收缩成圆角（shader 做金属度 + 粗糙度 + 高度场的插值），器件被表面张力拉正（自对中）；ESOP8 / VQFN 底部焊盘用 X 光线框展示（提示词第 11 条） |
| 外墙涂装自上而下 | 刷子蘸洗板水从上到下刷过，助焊剂残留（半透明棕色贴图）被擦除 |
| 楼层爆炸拆解 | **板子爆炸图**：器件抬起，显示每个器件的值和作用（可选） |
| 秋冬除夕 | **上电测试**：Type-C 线 / 锂电接入，万用表七段数字 `BAT 3.42 → 4.20 V`、`VOUT 5.00 V` 恒定，4 颗 LED 依次点亮；测试点高亮 |
| 结尾数据卡「砖 97,011 块…」 | 「这块板子，用了」：器件 25 个 / 焊盘 68 个 / 锡膏 0.4 g / 焊接 6 min / 输入 5 V / 输出 5 V 2 A / 造价 ≈ 12 元 |
| 砖 / 钢筋 / 混凝土计数 | 左下角：已焊器件数 / 焊盘温度 ℃（热风段）/ 板上电压 |

**和提示词原文的差距**，必须说清楚：
- 提示词第 3、4 条要的是「电子显微镜 + 焊盘熔化凝固特写 + 解压效果」。代码渲染能做「风格化微缩」的熔锡（样片那种质感），做不到显微镜实拍那种锡的真实流动、烟雾、助焊剂沸腾。解压感主要靠**音效设计**（风枪声、镊子碰板声、锡「啪」一下润湿的声音）和节奏，画面是干净的工程动画。
- 如果你坚持照片级的熔锡特写，那一段仍要走 `docs/01` 的 AI 生成或实拍，再合进 Remotion 时间线。两种可以混用：全片代码渲染，只有 4–6 个「熔锡特写」镜头用 AI 生成素材。

### 3.2 教学视频（sheet 5–6）

直接对应，提示词本身就要求 Remotion + SVG + 程序绘制表格。样片额外教会我们的是：
- 开场也可以用「提示词即开场」+「扫描一张电阻实物照片」的套路，比干巴巴的 PCB 推镜更有网感；
- 8 颗电阻从 PCB 升起排列（sheet 5 第一幕）= 样片「楼层爆炸拆解」的同一种动画；
- 功率柱状图、丝印拆解「10 | 3」= 样片的计数器和 HUD，数据驱动；
- 可以给整段视频也加一个右上角的「进度/章节」HUD，保持系列视频的视觉统一。

## 4. 共用工程的架构（6 个视频共用，改数据不改代码）

```
remotion-project/
├─ src/
│  ├─ hud/            章节标签、天数/器件计数器、用料计数、双语字幕、终端打字、SCAN 框   ← 6 个视频共用
│  ├─ three/          摄像机样条、DoF/Bloom、粒子、InstancedMesh 逐个出现、X 光线框、爆炸拆解
│  ├─ scenes/
│  │   ├─ pcb/        PCB 板体、焊盘、锡膏、器件 glTF、镊子、热风枪、万用表（01–04 共用）
│  │   ├─ resistor/   05
│  │   └─ capacitor/  06
│  └─ Root.tsx        每个视频一个 <Composition>，读各自的 data/*.json
├─ data/
│  ├─ 01-ip5306.json  BOM、放置顺序、每个器件的帧区间、测试读数曲线、字幕
│  ├─ 02-adp150.json
│  ├─ …
│  └─ 05-resistor.json  封装尺寸 / 功率 / 丝印规则（sheet 5 要求的结构化数据源）
└─ assets/
   ├─ pcb/01-ip5306/  KiCad 工程导出：board.glb（或 VRML）、焊盘坐标 JSON、原理图 SVG
   └─ fonts/          中文字体（思源黑体）+ 等宽字体（HUD）
```

PCB 来源：用 KiCad 真的把 4 块板画出来（反正要用真实焊盘坐标），`kicad-cli pcb export glb` 导出 3D，再用一个脚本从 `.kicad_pcb` 抽焊盘中心和器件位号写成 JSON，Three.js 据此摆器件、放锡膏、定镊子落点。这样 4 块板只是 4 份数据，动画代码一份。

渲染：Remotion `npx remotion render`，1080p60 或 4K30（sheet 5 要 4K）。60 s 的 3D 场景在无 GPU 的云机器上渲染 3600 帧要按小时计，建议开发在本地带 GPU 的机器上做，或者渲染时用 `--gl=angle` / swiftshader 并接受慢。
